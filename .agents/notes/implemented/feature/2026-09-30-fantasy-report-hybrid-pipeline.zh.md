# Agent Note：Fantasy 报告混合流水线

状态：已实现

[English](2026-09-30-fantasy-report-hybrid-pipeline.md) | 中文

## 问题

每周 Fantasy 报告曾要求一个撰写阶段输出一份庞大而死板的 JSON 文档：每名球员一行并附带引文事实、阵容、行动、关键抉择和注意事项，之后再由审阅和修复阶段打补丁。实际运行不断因格式漂移而失败：审阅阶段写出伪工具调用，修复阶段用 `id` 而不是 `player` 作为行键，撰写阶段用球员姓名而不是 `P1` 作为行键，修复阶段还会凭空添加字段。任何一次漂移都会扣留整份报告，尽管文档的大部分内容都是代码早已掌握的事实和算术。

## 决策

确定性的工作全部交给代码，模型只做小型判断，并且每项判断都单独验证。代码读取 Yahoo 阵容、阵容位、对阵和自由球员；以姓名采纳收集新闻并截取原文摘录；在灵活位资格、可出场性和阵容位锁定的约束下搜索 Yahoo 预测分数总和最高的合法阵容；标出接近的抉择；为薄弱位置筛选自由球员候选；并渲染 Markdown 报告。模型阶段只回答固定形状：按 `playersPerStage` 分批给出逐名球员的 `START`、`SIT`、`FLEX` 或 `HOLD` 决定，附简短理由和所引来源编号；为每对被标出的球员写一段比较；在候选 ID 中挑选自由球员；做一次理由核查；以及写一段 3 到 5 句的摘要。

验证按项进行。不合格或缺失的球员会在只含这些 ID 的请求中再问一次，否则保留代码默认值并附上直白的 Yahoo 理由；代码只以合法替换的方式应用模型决定，并拒绝不可出场球员的首发和对被锁定球员的移动；不合格的比较或选择会被省略；不可用的摘要由代码摘要替代；被标为无依据的理由换成直白的 Yahoo 理由。报告在注意事项中列出每个降级的部分，除非 Yahoo 事实读取失败或没有任何模型阶段给出可用回答，否则都会发布。每次模型调用都通过研究工作流运行器保持为有日志的阶段 Session，沿用现有的阶段系统提示词机制和 JSON 纠正轮次；提示词版本为 `fantasy-weekly-v5`。撰写、审阅和修复阶段及其提示词和配置字段已移除；报告标签和运行历史保持原有格式，因此早先的运行仍可解析。

## 考虑过的替代方案

- **保留整体草稿并容忍更多漂移** — 未采用，因为每新增一个别名或修复规则只能修好一种已观察到的失败，而其他任何漂移仍会扣留整份报告。
- **让模型选择阵容再由代码检查** — 未采用，因为合法且预测分数最高的阵容是一个代码可以精确计算的小型搜索；模型真正有用的贡献是决定是否偏离，而代码可以逐个替换地接受或拒绝。
- **理由核查标出问题时扣留报告** — 未采用，因为被标出的理由会换成直白的 Yahoo 理由；扣留会再次让一个不良条目阻挡整份报告。
- **通过 LLM 接缝请求结构化输出** — 暂缓；LLM 调用配置没有响应格式字段，而逐项解析的小型固定选项回答已经消除了这种失败模式。

## 影响

现在一个不良回答只会降级一行、一对、一个选择或摘要，而不是整份报告。报告更短、更统一：以决定、接近的抉择和自由球员建议取代自由形式的行动和抉择。匿名化的 Yahoo 阵容抓取不含逐名球员的预测分数，因此在提供方请求预测统计数据之前，阵容搜索保留当前 Yahoo 首发（不可出场者除外），接近的抉择只来自状态不确定的首发。自由球员候选只有 Yahoo 事实。关于[原生每周报告](2026-09-27-native-fantasy-weekly-reports.zh.md)和[修复 `id` 别名](../bug-fix/2026-09-30-fantasy-reports-repair-and-on-demand.zh.md)的早先笔记描述的是已被取代的撰写、审阅与修复策略。
