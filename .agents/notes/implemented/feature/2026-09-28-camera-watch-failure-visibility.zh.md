# Agent Note: 摄像头监视报告失效的分类器

Status: implemented

[English](2026-09-28-camera-watch-failure-visibility.md) | 中文

## 问题

摄像头监视插件在每个事件时才惰性解析模型路由，因为提供方在监视插件应用之后注册。2026-09-28 的 04:07 到 07:51 之间，配置的路由无法解析：pi-ai 适配器拒绝了一个 `reasoningEfforts` 只声明 `off` 的模型。每个事件的分类都以 `MODEL_UNAVAILABLE` 失败，而分类失败的移动事件没有通知原因，因此约四个小时内没有发出任何消息，除了每个事件一行错误日志之外没有任何迹象显示故障。

## 决策

**在路由的提供方注册时检查路由。** 监视插件按事件时完全相同的方式解析路由（包括图像输入检查）：启动时路由的提供方已注册则立即解析，此后在每次该提供方刚出现的 `llm/adapters-updated` 时解析。提供方是 `modelSelection` 的提供方，未设置时是当时主机默认模型的提供方。成功时记录 `camera-watch: classifying with <provider>/<model>`；失败时记录以 `camera-watch: model route check failed:` 开头、附带原因链的错误，并发起失败通知。检查从不抛出异常，因此失效的路由不会中止主机，逐事件解析保持不变。pi-ai 适配器先注册路由，再拒绝解析配置错误的模型，因此在本次事故的情形下注册表确实会报告该提供方。

**通过 `camera/notice` 发送限频的失败通知。** 路由失败（`MODEL_UNAVAILABLE`、`MODEL_NOT_VISION`）无论来自检查还是事件，都会立即发起通知；`TIMEOUT`、`TURN_FAILED`、`NO_ANSWER` 和 `SESSION_FAILED` 在连续 `failureNoticeThreshold` 次（默认 3）后发起通知，任何得到回答的分类都会结束连续计数。每个 `failureNoticeIntervalMs`（默认六小时）内最多发起一条失败通知。文本为 `⚠️ Camera classification is failing (<code>: <cause>). Motion alerts are paused; doorbell presses still post.`，路由失败的原因取最内层错误的第一行并限制在 200 个字符内，门铃分句只在 `policy.ding` 开启时出现。失败通知之后第一次得到回答的分类会发送 `Camera classification recovered.`。两者都写入日志，配置了 `deliverChannelId` 时还会交接到该频道。

**用稳定 ID 代替持久化状态。** 失败通知的 ID 指向包含它、按 Unix 纪元对齐的 `failureNoticeIntervalMs` 窗口：`camera-watch:classification-failing:<窗口起点>`；恢复消息在其后追加 `:recovered`。Discord 发件箱会忽略已持有的 ID，因此在同一窗口内重启不会重复发送同一条通知。通知间隔、连续失败计数和待发送的恢复消息保存在内存中。

## 考虑过的替代方案

**重新在加载时校验路由。** 提供方在监视插件应用之后注册，因此加载时检查会因加载顺序让正确的部署失败，这正是解析移到每个事件的原因。

**等待主机就绪事件。** Loader 和应用启动不发布“所有插件已应用”事件，而且提供方可能在其设置加载后才更晚注册；注册表自身的变更事件才是路由变得可解析的时刻。

**把失败状态持久化到历史存储域。** 这能让通知间隔和待发送的恢复消息跨重启保留，但要为历史增加一张表和一个存储域版本，而这个限频最坏的结果只是重复一条通知或缺少一条恢复消息。

**每个失败的移动事件都通知。** 这会让一次故障在数小时内变成每次移动警报一条消息。

## 影响

配置错误的路由会在启动时（提供方注册后）报告，遇到它的第一个事件也会报告，二者都受同一通知间隔约束。跨越窗口边界的重启可能重复一条失败通知，重启前已通知的失败不会有恢复消息。从不注册的提供方不会被检查，只有事件会报告它。保持提供方已注册的路由修改在事件解析之前不会被重新检查。

监视插件的测试固定了启动时和延迟注册后的检查、检查失败的日志和通知、重复路由失败时每个间隔一条通知、轮次失败阈值及其重置、只发一条恢复消息、未配置频道时只写日志，以及两个配置字段的取值范围。`camera-watch` 会话快照没有变化，因为其回放路由可以解析。
