# Agent Note: 已配置的 Web 抓取主机名屏蔽

Status: implemented

[English](2026-09-27-web-fetch-blocked-hosts.md) | 中文

## 问题

部署可能需要在匿名 Web 抓取时拒绝已知的外部主机名。公开地址检查无法表达这种选择，因为这些主机名可能解析到公开 IP 地址。

## 决策

`web-fetch-http.blockedHosts` 接受裸 DNS 主机名。插件加载时验证每个条目，并规范化大小写和一个尾随点。抓取提供方对请求及重定向主机名执行同样的规范化，然后在接触目标前以 `WEB_BLOCKED_URL` 拒绝精确匹配及子域名。DNS 标签边界使相似但无关的名称保持可用。

该列表只用于主机名规范检查，不是 IP 或 SSRF 策略。直接连接保留公开地址校验和连接固定。配置代理时，由代理解析目标并负责目标限制；代理请求不运行本地公开地址检查。

## 考虑过的替代方案

**直接比较 URL 解析后的主机名。** WHATWG URL 解析会保留 DNS 尾随点，因此没有尾随点的配置条目会漏掉等价的请求主机名。

**按原始字符串后缀屏蔽。** 没有 DNS 标签边界的后缀也会屏蔽 `notaliyuncs.com` 等无关的相似主机名。

## 后果

操作员可以拒绝指定主机及其子域名，而无需修改地址策略。格式错误的条目在插件加载时失败。该列表不能替代直接连接的地址检查或代理自己的目标策略；即使跨源规则也会拒绝目标，重定向目标仍会接受主机名检查。
