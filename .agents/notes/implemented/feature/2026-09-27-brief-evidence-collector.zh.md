# Agent Note: 为 cron 简报收集有界证据

Status: implemented

[English](2026-09-27-brief-evidence-collector.md) | 中文

## 问题

让模型自行抓取并挑选标题会耗费模型时间，而且来源失败可能变成未标明的遗漏。Beardy 的个人配置中已有 RSS/Atom 与天气收集器，但该文件插件不能成为 Beardy bundle 声明的包依赖。它指定的模型路线也不在当前个人配置中。

## 决定

`@deepseek-ai/dsh-brief-collector` 在专用 agent 预设内运行。在 `agent/pre-step` 阶段，它通过 `ctx.web` 获取配置的 feed 与天气，将具名 cron 输入替换为完整、有界的 JSON 数据包，并保留输入的 cron 来源及身份。它将工具限制为空。部分失败保留为具名缺口；如果全部来源失败或数据包超限，pre-step 会在 step 开始前抛出错误，本轮因此以错误结束且不发出模型请求，cron 记录失败运行。全部失败时的错误会列出每个来源的原因。cron 任务负责 `modelSelection`；收集器仅通过 `agent/request` 限制回答 token 数。Beardy 声明该包为依赖并列出一个禁用的 Host 条目；只有个人预设会挂载它，因为工具限制需要 Agent 作用域，Host 级挂载会在加载时失败。

## 考虑过的替代方案

没有采用通用的 cron 命令前置步骤。现有收集器是 Cordis 插件，不是可执行程序，并且已经使用 Harness Web 能力。只为一个任务加入命令前置步骤，会增加进程启动及新的命令配置权限。如果第二个独立任务需要任意进程收集，再根据该用途确定命令、沙箱、输出与日志规则。

没有保留原型在请求阶段覆盖提供者与推理强度的做法，因为 cron 现在会在创建 Session 时验证并记录任务级 `modelSelection`，本地模型控制也会在触发前检查该路线。简报插件仍设置 `maxTokens`，因为该选择不包含此值。

没有沿用原型在全部来源不可用时仍发送数据包的做法：模型会在没有证据的情况下撰写简报，投递也会把故障当作正常结果掩盖。

## 后果

模型只看到已记录的证据包，没有收集工具。Cron 历史和结果投递将全部收集失败保留为失败运行；部分成功的数据包则告诉模型哪些具名来源不可用。部署必须显式提供全部来源 URL 和正数限制；bundle 不提供 feed、目标地址或模型路线。解析范围仍为 RSS/Atom 与 wttr.in 风格的预报 JSON，报道按有界轮询选择，而不进行编辑排序。
