# Agent Note: 以 Session 保存的原生研究运行

Status: implemented

[English](2026-09-27-session-backed-research-runs.md) | 中文

## 问题

研究运行可能比调用方的轮次或进程存活更久。仅存在于进程中的任务记录无法让重启后的 Harness 判断工作是否完成、保留了哪些来源，或者谁可以读取报告。研究引擎还需要持久记录其决策，但编排事件不能冒充模型请求历史。

## 决策

`ctx.research` 将服务定义与本地存储提供方分开。每个运行拥有一个持久化的空闲 Agent/Session，其 ID 就是带品牌类型的运行 ID。运行的 `research/started` 事件刷新后，调用方 Session 才记录 `research/linked`。运行 Session 保存检查点和一个终态结果。列表从持久化的运行 Session 投影，不以进程内索引为准。提供方在返回状态、报告或取消结果前检查已保存的所有者；配置的 profile 命名空间仅适用于单用户部署。

调用方的精确 `requestKey` 可在启动结果不明确时找回现有运行。调用方刷新失败可能留下尚未启动的运行记录；重启后首次访问时，提供方把非终态记录标记为 `interrupted`。它不会自动重放网页请求或模型调用。取消操作只允许一个终态胜出。报告和证据文件先作为不可变附件保存，其引用随后才写入终态事件。读取方返回报告前验证两个文件。

本地引擎为每次模型调用创建短生命周期的子 Agent/Session，其 `parentSession` 指向运行。它限制模型准入和页面证据，在运行中记录每次搜索、抓取、规范化发现与草稿，并在引用附件前提交精确抓取文本。子 Session 能重建模型请求，运行编排不会冒充对话历史。默认 Session 列表和 `session_search` 根据父会话的 `rp-native-` 前缀排除这些子 Session；明确按 ID 读取和指定父会话的搜索仍可访问。引擎在阶段中拒绝向模型声明工具，也拒绝执行工具。`deep_research` 工具从调用方 Session 推导所有者，以精确的工具调用 ID 作为启动键，并通过分页读取报告，避免把完整报告放入模型可见文本。原生与 Odysseus 工具插件拒绝同时挂载；Beardy 通过配置档补丁选择其一。

## 考虑过的替代方案

- **用 `jobs-local` 作为持久权威** — 它的记录和所有权只存在于进程中，重启后消失，因此未采用。
- **另建研究数据库作为权威** — 它会重复 Session 的顺序记录，并要求两个存储之间的原子提交协议，因此未采用。
- **自动继续中断的工作** — 最后一次检查点之后可能已经发生模型或网页请求，自动恢复可能悄悄重复外部工作，因此未采用。
- **在终态事件中保存可变报告路径** — 后续文件变动可能让历史完成事件指向不同内容，因此未采用。

## 后果

运行日志在重启后保留身份、所有权、进度及来源结果；调用方关联失败后，所有者仍可找到运行。附件若没有引用它的事件，会留下不可达对象，这比暴露指向缺失内容的事件更安全。引擎在中断后不会自动重放工作；引用 URL 检查只证明来源，不核实单项事实。普通历史展示虽然省略阶段 Session，但仍可按明确 ID 访问。模型可在进程重启后凭 ID 重新打开已完成报告；查看器在第一页收到完整报告元数据，而模型读取有界分页。
