# Agent Note：Discord 用户通道

Status: implemented

[English](2026-09-23-discord-user-lanes.md) | 中文

## Problem

同一个 Discord 网关可能服务于需要不同工作区、预设和工具访问权限的用户。仅凭频道记录无法授权命令：其中可能指向用户获得受限通道前开启的会话。Discord 的全局命令菜单也没有按用户区分可见性的规则。

## Decision

网关为共享服务器频道保留默认通道，并可为允许清单中的私信用户配置专属通道。每个专属通道选择工作区、agent 预设、权限预设、工具筛选器，以及额外排除的预设命令。拥有专属通道的用户不能在服务器频道中通过此网关操作。持久记录、存活 agent 和尚在开启的会话都保留所属通道标识。

每条已准入消息、文本命令、原生命令和提示控件都按发起者确定当前通道。命令读取状态或在 agent 上执行前，路由器会取消其他通道尚在开启的会话，并释放属于其他通道的记录和 agent。`/help` 读取发起者预设的命令目录，无需开启会话。当前通道没有存活 agent 时，预设命令会要求先发送消息。待决回答要求发起者通道同时匹配记录与存活 agent。同一共享服务器频道内的已准入默认通道用户仍共同拥有提示回答权限。

Discord 的全局原生命令菜单包含所有已配置通道命令的并集。原生派发先按发起者通道检查命令目录，再委托与文本命令相同的执行器。因此全局菜单可能展示某个用户无法运行的命令；`/help` 只显示该用户可用的命令。

## Alternatives considered

**命令信任频道记录。** 普通消息到来之前，旧 agent 的权限会在通道限制后继续有效，因此每条命令都必须核对发起者。

**通道变更后每条命令都开启新会话。** 网关命令无需会话，而预设命令可能启动模型轮次。释放旧会话并要求先发送消息，使转换明确，也不会只为回答 `/help` 或 `/status` 而创建会话。

**原生菜单只发布默认通道命令。** 其他预设的用户将不得不依赖未在菜单中说明的文本命令。并集让命令可被发现，原生派发仍按发起者通道执行权限检查。

## Consequences

拥有专属通道的用户不能通过此网关参与服务器频道。通道变更后的下一条已准入消息或命令会关闭旧对话；旧会话的历史不会迁移。原生菜单的可见范围大于命令权限。同一服务器频道内的默认通道用户可以回答彼此的待决提示，因此需要单独审批权限的部署必须将用户放在不同频道或通道。通道测试覆盖过时的存活与持久记录、文本与原生命令、首条消息前的帮助、待决回答以及共享服务器频道行为。
