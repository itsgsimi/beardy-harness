# Agent Note: Session 范围的技能提醒与草稿检查

Status: implemented

[English](2026-09-27-skill-nudge-quality.md) | 中文

## Problem

Beardy 一个月产生了 104 次技能提醒和 55 次创建，但只有 30 次技能加载。频繁的提醒促成了很少复用的狭窄文件，而 6–30 KB 的用户技能在审批前缺少大小上限和草稿检查。

## Decision

`tool-skill` 从 Session 日志投影已完成的工具结果、模型成功的 `skill` 加载、用户的 `skill-invocation` 消息和既有的 `skill-nudge` 消息。已完成轮次若有至少 `nudgeAfterToolCalls` 个结果且未加载技能，就可在下一条获准请求中加入一次提醒。投影在恢复时重建，并使每个 Session 最多收到一次提醒；持久来源为子 agent 的会话仍被排除。Beardy Web 和 Discord 的阈值为 20，无人值守通道仍不自动编写技能。此时机和生命周期取代了[最初的技能管理决策](2026-09-05-skill-nudge-and-user-scope.zh.md)中的逐轮次监听器。

`skill_manage check` 不变更文件也不请求审批，运行与创建、更新相同的验证。结构化结果包含错误、警告和规范化正文的字节数。无效名称、缺少必填字段、重复的 frontmatter，以及超过已验证 `skillBodyMaxBytes` 上限的正文属于硬错误；薄弱的调用指引、过于简略的草稿和目录重叠属于建议性警告。创建和更新会在审批前拒绝硬错误，再在审批原因中显示警告及有界的差异片段。默认上限为 32768 个 UTF-8 字节，包含结尾换行。现有技能不会被改写，加载时也不会因此被拒绝。

## Alternatives considered

**保留进程内逐轮次计数。** 它无法确认轮次已经完成，也无法确认同一 Session 的较早生命周期已经发出提醒。Session 投影从持久记录中推导两项事实。

**写入前强制要求完美的调用说明。** 简短的 `whenToUse` 或目录相似性可能合理；警告允许作者判断，同时阻止格式错误和过大的正文进入审批。

**在审批中显示整个技能。** 用户技能可达数万字节。审批原因只显示有界的改动片段和检查摘要，保持可读。

## Consequences

每个 Session 最多新增一条留存的提醒消息，且只在已完成轮次后出现。`check` 和变更工具的结果通过普通工具历史保留模型可见的检查事实。正文上限适用于新写入，不限制加载现有提供方的技能。每周审阅仍需有界的 Session 清单，才能跨 Session 统计加载次数；此改动没有新增计数存储或自主整理流程。
