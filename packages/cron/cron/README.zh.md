# @deepseek-ai/dsh-cron

[English](README.md) | 中文

## 概述

本包让 agent 在无人看管时按时间表运行。每个配置的任务写明一个 cron 表达式、一个 IANA 时区、一段提示词，以及塑造该次运行的一对预设：agent 预设决定组合（composition），权限预设决定它能在工作区里做什么。计划触发时，本包开启一个全新会话，挂载该组合，把提示词作为一条带 cron 来源信息的用户消息交进去，并记录这次运行如何结束——已回答、无文本回答、超时、或失败。计划在配置加载时即被校验，因此不可用的表达式或重复的任务名会让启动失败，而不是安静地永不触发。若下一次触发到来时上一次运行仍在进行，该任务不会被启动两次。任务只来自配置；运行时没有任何机制创建或修改它们。

## 模型体验

### 触发提示词

#### 模型看到什么

一次运行的首个请求把任务的 `prompt` 作为一条用户角色（user-role）消息带进去，并带有由各界面渲染成提示的来源信息：任务名与计划触发时间。该会话没有更早的轮次，也没有其他输入来源，因此这段提示词就是全部任务书；运行需要知道的一切，要么写在提示词里，要么能通过已挂载组合的工具取得。

#### Token 影响

每次触发对应一条用户消息，加上该运行自身工具调用产生的消息。每次运行都是独立会话，因此成本按触发重复，而不是累积进一段很长的对话；`turnTimeoutMs` 限制单次运行最多持续多久。

#### KV Cache 影响

每次触发都启动一个新会话，其预设组合构成它自己的初始前缀，因此各次运行之间不共享缓存历史。在同一次运行内部，追加的轮次照常可复用。

## 已知限制与后续工作

<a id="known-limitations-and-deferred-work"></a>

- **任务只能来自配置** —— 没有任何 Service 方法或面向模型的工具可以创建、修改、暂停或删除任务；要加一个任务就得改配置并重启。运行时任务是这一特性的下一块内容。
- **自身不做投递** —— 一次运行只能通过其预设挂载的工具影响外部世界，例如 `discord_send`；没有投递工具时，回答只留在会话日志里。
- **停机期间错过的触发不补跑** —— 进程停止期间本应触发的计划会在恢复后被跳过；下一个计划时间照常运行。
- **每个任务只重叠一次触发** —— 仍在运行的任务会让下一次触发被记为跳过而不是排队，因此单次运行时长超过自身周期就会失去这些触发。
- **会话会累积** —— 内存中已挂载的运行超过 `maxLiveRuns` 时按最旧优先释放，而每次触发创建的持久会话仍留在磁盘上；本包不删除任何东西。


<a id="dev-note"></a>
### 开发备注

<details>
<summary>维护者的工作上下文——点击展开</summary>

`schedule.ts` 把 croner 包在 `Scheduler` 接缝（seam）之后（`cronerScheduler`，以及只校验表达式而不调度的 `assertSchedule`），因此测试可以用假调度器挂载任务，同时用真实调度器证明一秒周期的表达式确实触发。`launch.ts` 负责会话创建顺序——解析 agent 预设、解析权限预设、注册工作区、生成会话 id、`agents.create`、attach、应用权限、命名——任一后续步骤失败时回滚为 detach 加 dispose。`index.ts` 校验配置、跳过重叠触发并维护 in-flight 守卫；`apply` 读取解析后的配置，因此实际运行的就是打过补丁的值。

</details>

**运行时不变量：** 不发布伴生包。调度、定时器与已挂载会话都归属于该插件 fiber，停止时一并停止；`tests/loader-composition.spec.ts` 会真正启动 Loader，证明不可用的配置拒绝加载。
